## 1. 产品定位


**一句话定位（草案）**：一款本地优先、快速、界面克制的桌面 Markdown 编辑器。

三个关键词：
212

- **本地优先**：文件就是普通的 `.md` 文件躺在用户自己的文件夹里，没有私有格式、没有云端锁定。数据永远属于用户。
- **快**：启动秒开、大文件（几 MB 的 md）不卡、输入零延迟。
- **克制**：不做全家桶。核心是把"写"这件事做到舒服，功能按需生长。

### 参照系

| 竞品 | 借鉴 | 不学它 |
|---|---|---|
| Typora | 所见即所得的沉浸写作体验 | 商业闭源 |
| Obsidian | 文件夹即工作区、双链 | 功能过重，学习成本高 |
| MarkText / Zettlr | 开源、跨平台、干净 | 性能与稳定性问题较多 |

### 差异化机会（候选）

- 中文写作体验优先（IME 兼容、中英文混排间距、标点智能处理）
- 启动速度与内存占用显著优于 Electron 系竞品（Tauri 天然优势）
- 极简但精致的默认主题 + 深度主题定制能力

## 2. 目标用户与场景

- **主场景 A — 单篇写作**：打开一个 `.md` 文件，写博客/文档/笔记，改完保存关闭。
- **主场景 B — 笔记库管理**：把一个文件夹当工作区（vault），左侧树形浏览、多标签页切换、全局搜索。
- **次场景 C — 导出分发**：导出 HTML / PDF 用于发布或分享。

## 3. 功能需求（分级）

> P0 = MVP 必须；P1 = 第二阶段；P2 = 远期/待定

### 3.1 编辑核心 (P0)

| 功能 | 说明 |
|---|---|
| Markdown 编辑 | 源码模式编辑，语法高亮 |
| 实时预览 | 左右分栏，滚动同步 |
| GFM 支持 | 表格、任务列表、删除线、脚注、代码块高亮 |
| 数学公式 | KaTeX 渲染 `$...$` 与 `$$...$$` |
| 打开/保存 | 系统对话框选择文件；Ctrl/Cmd+S 保存 |
| 未保存保护 | 关闭前提示；崩溃后可恢复 |

### 3.2 编辑体验 (P1)

- 快捷键加粗/斜体/插入链接图片/代码块（选中文本包裹；含中文输入法组字期间的可用性验证）
- 列表自动续行（回车自动补 `-`，空项回车退出列表）
- 大纲面板（侧栏「大纲」页签，点击跳转，滚动高亮当前章节）
- 字数统计（字符数 / 词数 / 预计阅读时长）
- 查找替换（编辑器内）
- 图片处理链路（重点）：粘贴/拖入图片自动落盘到 `assets/` 并插入相对路径引用；预览经 asset 协议安全渲染，详见 §4.6-A
- 中文写作增强（差异化重点）：中西文盘古间距（仅渲染层，永不改源文件）；中英文标点智能配对（可开关），详见 §4.6-E
- 自动保存（可配置开关 + 延迟时间）

### 3.3 文件与工作区（核心能力）

- 工作区模式：打开文件夹 → 树形侧边栏 → 新建/重命名/删除
- 多标签页打开多个文件
- 最近工作区列表（持久化）
- 文件变更监听：外部修改时提示重新加载（tauri-plugin-fs watch）
- 工作区内全局搜索（P2，M4 stretch）

### 3.4 外观与设置 (P1)

- 明暗双主题，跟随系统
- 无边框自定义标题栏（更精致，也统一三平台观感）
- 设置页：主题 / 字体字号 / 自动保存 / 预览同步方式

### 3.5 导出

- **导出 HTML（P1，M4）**：内联样式单文件。纯前端管道，无平台差异，优先实现
- 导出 PDF（P2）：WebView 打印管线在 macOS 表现良好，但 Windows 端打印对话框拦截行为差异大，视难度后置；备选路径是“打开导出的 HTML → 浏览器/系统打印”
- 复制为富文本（P2，粘贴到公众号/飞书等）

### 3.6 明确不做（v1 范围外)

- 云同步 / 账号体系
- 双向链接、知识图谱
- 协同编辑
- 移动端

## 4. 技术方案

### 4.1 已确定的技术栈

```
┌─────────────────────────────────────────┐
│  前端: SvelteKit 2 (SPA, ssr=false)      │
│        Svelte 5 runes + TypeScript       │
├─────────────────────────────────────────┤
│  Tauri 2 (Rust)                          │
│  - 文件 IO / 文件监听 / 对话框 → Rust 侧 │
│  - 窗口管理 / 自定义标题栏              │
└─────────────────────────────────────────┘
```

### 4.2 关键选型（需要拍板）

#### ⭐ 决策 1：编辑器内核

| 方案 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A. CodeMirror 6** | 源码+分栏预览 | 最成熟稳定、性能好、可控性强、生态大 | 不是所见即所得，需自建预览层 |
| **B. Milkdown** | 所见即所得 (基于 ProseMirror) | 打字即渲染，Typora 式体验 | 定制曲线陡、IME 边角问题需验证 |
| **C. CodeMirror 6 起步，后期评估加 Milkdown 双模式** | 渐进式 | MVP 快、风险低 | 双模式意味着两套维护成本 |

**已定（D1）**：采用方案 A —— **CodeMirror 6 + remark 统一渲染管道**（源码 + 实时预览）。CM6 是确定性最强的地基；所见即所得仅作远期评估，不进 v1 范围。

#### ⭐ 决策 2：Markdown 解析管道

建议 `unified` 生态：`remark-parse` + `remark-gfm` + `remark-math` + `rehype-katex` + `rehype-highlight`（或 shiki）。一条管道同时服务预览渲染和未来导出 HTML。

#### ✅ 决策 3：产品形态深度（已定）

**采用文件夹工作区模型**（对标 Obsidian 的 vault）：打开一个文件夹作为工作区，树形浏览 + 多标签编辑。这是产品核心而非附加项，里程碑据此重排（见第 5 节）：M1 先做编辑闭环，M2 上工作区。

### 4.3 架构分层

```
src/
  lib/
    editor/        # CM6 封装：快捷键、语法高亮、命令、history
    markdown/      # unified 管道封装（渲染 + 块级增量 diff）
    preview/       # 预览容器：data-src-line 锚点、滚动同步插值
    stores/        # Svelte 5 runes 全局状态：
                   #   documents(标签元信息)、settings、workspace
                   #   ⚠️ 不存放文档正文与撤销栈（见原则 2/3）
    components/    # TitleBar / TabBar / Sidebar / StatusBar ...
    commands/      # invoke() 的类型化封装 (open_file/save_file/...)
src-tauri/
  src/
    fs.rs          # 读写、路径解析、工作区沙箱校验
    watch.rs       # 文件监听：防抖 + 自身写入抑制
    main.rs
```

原则：

1. **所有磁盘 IO 走 Rust command**，前端不碰裸路径权限；capability 白名单最小化授权。
2. **文档正文的唯一事实源是 CM6 的 EditorState**。每个标签页持有独立 `EditorState`（含未保存内容），切换标签不重建；Svelte 只单向订阅派生标志（dirty、光标位置、字数），绝不把正文镜像进 rune 再反向驱动编辑器。
3. **撤销/重做归属 CM6 内置 `history()` 扩展**，随各标签页的 EditorState 天然隔离；全局菜单/快捷键只向活动实例转发命令，不在 Svelte 全局状态里自建撤销栈。

### 4.4 需要新增的依赖

前端：`@codemirror/*`、`unified` 系列、`katex`、`svelte-highlight` 或 `shiki`
Rust：`tauri-plugin-dialog`、`tauri-plugin-fs`（watch 权限）、`tauri-plugin-window-state`

### 4.5 必须提前验证的风险点（技术 Spike）

> Spike 在对应里程碑最开头执行，结论回填本表。

| # | Spike | 验证内容 | 排期 |
|---|---|---|---|
| S1 | **IME 兼容性**（最高优先级） | WKWebView 下 CM6 组字事件 × 「runes 驱动异步防抖预览」的组合稳定性：拼音不截断、光标不跳跃；Cmd+B 等快捷键在组字期间的可达性 | M1 第一件事 |
| S2 | asset 协议动态授权 | 打开工作区时 `allow_directory` 运行时授权是否生效；含中文/空格子路径的 URL 编码 | M2 |
| S3 | 监听防环 | 自写抑制 + 内容比对在真实保存频率下零误报 | M3 |
| S4 | 大文件性能 | 1MB+ md 输入帧率；块级增量渲染的实测收益 | M3 |
| S5 | 自定义标题栏 | 拖拽区、红绿灯、全屏行为在 macOS 的表现 | M0 |

### 4.6 关键链路设计（v0.2 评审定稿）

#### A. 图片渲染与持久化链路

WebView 安全策略不允许 `<img>` 直接引用本地任意路径，因此：

1. `tauri.conf.json` 启用 `assetProtocol`，并在 **Rust 侧运行时动态授权**：用户打开工作区时调 `asset_protocol_scope.allow_directory(workspace_root, true)` 把整个工作区加入白名单——静态 scope 无法覆盖任意用户目录。
2. 渲染层：rehype 插件将 md 中的相对图片路径解析为 `convertFileSrc(绝对路径)` 的 asset URL；解析基准是**当前文件所在目录**，不是工作区根。
3. 写入链路：粘贴/拖入图片 → Rust command 校验扩展名与大小 → 落盘 `{当前目录}/assets/`（或工作区配置的图片目录）→ 插入相对路径引用。
4. 安全校验集中在 `fs.rs`：所有路径先 canonicalize，再断言位于工作区根内，拒绝越界访问与符号链接逃逸。

#### B. 文件监听防环（Watch Storm）

自动保存触发自身 watcher 会造成「保存→监听→提示重载」死循环，三层防御：

1. Rust 侧防抖：notify 事件聚合后统一推送（约 300ms 窗口）。
2. 自写抑制队列：应用每次写文件前登记 `(path, 内容哈希)`，watcher 事件命中队列则消费并忽略。
3. 兕底：提示重载前先比对磁盘内容与内存文档，一致则静默忽略。

#### C. 预览增量渲染（性能与 IME 的共同答案）

不做「每次击键全量重渲染」。文档按块切分（段落/标题/代码块/表格…），逐块哈希 diff，只 patch 变化块：

- 组字期间预览更新走**空闲防抖**（~200ms debounce），且渲染发生在独立 DOM 子树，物理上不可能打断编辑器组字；
- 大文件只重算受影响块，1MB 文档仍可保持流畅。

#### D. 双栏滚动同步

弃用百分比方案（公式/图片导致长文中严重错位）。渲染时给块级元素打上行号锚点 `data-src-line`（来自 remark 的 position 信息）；同步时取 CM6 视口顶部行号 → 二分查找最近锚点对 → 线性插值得目标 scrollTop，双向同策略。

#### E. 中文写作增强实现位

- **中西文间距**：优先用原生 CSS `text-autospace`（新版 WKWebView/Safari 已支持，零成本零污染），旧环境回退到渲染层 rehype 处理；任何情况下不改用户源文件。
- **标点智能配对**：CM6 keymap 层按上下文（普通文本 vs 代码块内）区分处理引号/括号配对，提供设置开关。

## 7. UI 设计方向：「深空 + 极光」（已定稿）

> 判断标准只有一个：打开 App 的第一眼，它像不像一件被认真做出来的工具。

### 7.1 气质关键词

**安静 · 锐利 · 留白。** 界面是暗房，内容是显影的照片。所有 chrome（边栏、标签条、状态栏）退成中性灰，唯一的品牌记忆点是一抹「极光」。

### 7.2 色彩

- **双主题**：Dark「深空」为主打默认（呼应 Aurora 之名）——带冷蓝调的近黑分层背景（如 `#0F1218`），不是死黑；Light「晨雾」为暖白纸感，跟随系统切换。
- **品牌 accent = 极光渐变**：`#5EEAD4`（青）→ `#818CF8`（靛紫）。极度克制地使用，只出现在：光标、文本选区、活动标签页指示线、链接色、focus ring。
- 其余全部用中性色阶（约 10 级灰），层级靠亮度差表达，而不是阴影。

### 7.3 布局

```
┌─────────────────────────────────────────────┐
│ ● ● ●            （无边框，红绿灯悬浮）      │
├──────┬──────────────────┬───────────────────┤
│ 侧栏 │   编辑器 (CM6)   │      预览         │
│ ─────│                  │                   │
│ 文件 │                  │                   │
│ ─────│                  │                   │
│ 大纲 │                  │                   │
├──────┴──────────────────┴───────────────────┤
│ 状态栏：字数 · 行列号 · 保存状态             │
└─────────────────────────────────────────────┘
```

- 侧栏放两个页签（**文件树 / 大纲**），节省横向空间；写作时侧栏整体可折叠。
- 底部 24px 细状态栏：字数统计、行列号、保存状态（已保存 / 未保存 / 自动保存中）。
- 标签页位于标题栏下方；非活动标签弱化显示。

### 7.4 字体排印（中文优先）

- UI 字体：系统字体栈（macOS PingFang SC / Windows 微软雅黑自动回退）。
- 预览正文：默认系统无衬线；设置中可切衬线（思源宋体）照顾长文阅读。
- 代码块：JetBrains Mono（随包内置子集，含中文回退链）。
- 正文行高 1.75，段落间距宽松；标点悬挂、中西混排间距等中文排版细节列远期。

### 7.5 质感与动效

- 扁平 + 1px hairline 分隔线，几乎不用投影；圆角统一 6px。
- 动效只用一种语言：150–200ms ease-out 微过渡（侧栏折叠、页签切换、弹层出入），不做弹簧、不做夸张动画。

### 7.6 参考坐标

Linear（克制的层次与对比度）、iA Writer（排印专注）、Obsidian（信息密度）、Bear（开箱即美的默认值）。
